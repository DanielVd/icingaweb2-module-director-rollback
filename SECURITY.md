# Security policy

## Versions and scope

The project is a development preview. There is no published supported-version policy. Include the affected version or commit and the Icinga Web 2, Director, PHP, and database versions in a report.

Report issues in this module, including permission bypasses, disclosure of protected configuration, and rollback operations that can alter objects outside the approved plan. Report issues isolated to Icinga Web 2, Director, or Icinga 2 through the upstream project's disclosure process.

## Private reporting

Use GitHub's [private vulnerability report form](https://github.com/DanielVd/icingaweb2-module-director-rollback/security/advisories/new). If you cannot access the form, open a [GitHub issue](https://github.com/DanielVd/icingaweb2-module-director-rollback/issues/new) asking how to contact the maintainer privately. Keep the public request generic and wait for a private channel before sharing details.

In the private report, include the affected component, versions, required permissions, impact, and minimal steps to reproduce on a test instance. Redact credentials and real monitoring data. Keep exploit details, request captures, and affected configuration out of public issues and pull requests.

## Handling and disclosure

Triage reports privately, confirm affected versions and impact, prepare and verify the fix, and coordinate the timing of an advisory with the reporter. An advisory should identify affected and fixed versions where known and provide practical mitigation or upgrade instructions. Response times and a patch cadence have yet to be established.
